## Provenance and scope

The [shared reference](../../../../.prompts/ui-feedback-and-layout-mockups.md) and the three batch briefs ([entries](../../../../.prompts/ui-feedback-and-layout-mockups-1-entries.md), [admin](../../../../.prompts/ui-feedback-and-layout-mockups-2-admin.md), [public and catalogue](../../../../.prompts/ui-feedback-and-layout-mockups-3-public-catalogue.md)) define coverage. Behaviour comes from the [proposal](../../../../openspec/changes/ui-feedback-and-layout/proposal.md), [design decisions D-1–7 and assumptions A-1–4](../../../../openspec/changes/ui-feedback-and-layout/design.md), and its [specification deltas](../../../../openspec/changes/ui-feedback-and-layout/specs/). Implemented templates, styles and controls in `web/projects/admin`, `web/projects/public`, `web/projects/ui` and `web/projects/catalogue` take precedence over older captures for existing content. [Visual direction §9.3](../../../herald-visual-direction.md) supplies the implemented corrections.

The prototype is a standalone renderer, replacing the earlier composition scaffold; it does not load `entries-states.js`. It reuses `style.css` and `access-states.css` tokens, plus the existing shared UI semantic colour tokens for Notice surfaces. Square corners, system sans-serif fallback, palette and spacing scale remain the incumbent system. Organisation, account, tournament, player and team names come from the entries fixtures. Each query is an independent snapshot: configuration counts and entry-page counts need not describe the same instant. Historical rows may contain a guest with a later active entry.

Only prototype files and capture documentation are changed. Production Angular, APIs, functional discovery, the visual direction and OpenSpec remain untouched. No commit is created.

## Reproduce

With the existing e2e Playwright dependencies and Google Chrome installed, run from the repository root:

```sh
node prototypes/frontend/tools/capture-feedback-layout.cjs
```

For cumulative batch captures, append `--batch=1` (43 PNGs), `--batch=2` (70 PNGs) or `--batch=3` (79 PNGs). `--interactions-only` exercises interactions without rewriting captures or the manifest. A smaller batch run rewrites the manifest for that batch; run the full script again before publishing the complete set.

The [manifest](manifest.json) records each state, batch, file URL, viewport, full-page capture, SHA-256 and per-capture checks. Capture uses installed Chrome, headless, direct `file://`, device scale 1, `en-GB`, Europe/Madrid and local assets. Viewports are **1440 × 1000**, **390 × 844** and, for the three width-cap examples, **1920 × 1080**. Full-page height can exceed viewport height. `capture=1` pauses toast expiry only for reproducible capture; normal review uses five-second timers paused while hovered or focused. Fonts and two animation frames settle before capture.

## Verification and limits

Every capture is checked for page errors, HTTP requests, horizontal overflow, labelled form controls, unique IDs and targets at least 44 px high. Dialog/drawer captures require focus inside the modal and a visible 3 px outline; drawer and aside dimensions are checked. Toast captures check that the visible portion of a primary action does not intersect the stack. All 79 PNG hashes must be distinct and match the manifest.

Interaction checks cover unknown-state fallback; modal focus trapping, Escape and focus return; busy dismissal/submission blocking; non-whitespace private reasons; retry input retention; history disclosure and omission; toast dismissal, five-second expiry, focus pause and release of reserved space; capacity-summary field focus; declined discard retaining input; edits blocking registration changes; and layout at 699, 700, 1199 and 1200 px. Screenshots are inspected through labelled contact sheets and full-resolution samples.

Native HTML dialogs supply modality in this documentation prototype; this does not choose the production primitive. Fixtures perform no server requests, persistence, authorisation or revision reconciliation. Retry retains input and explains that no request was sent. Catalogue recovery is a local demonstration. These checks do not certify production accessibility or screen-reader output.

## Visual decisions not settled by the sources

- **All modal states:** focus starts on the leaving action for destructive confirmations, on the private-reason field for admission and on the name field for drawers. A busy cancellation focuses its heading because its controls are disabled. Native backdrop opacity uses the incumbent graphite. While a modal is open the inert workspace is clipped to the viewport so full-page capture cannot show undimmed off-screen rows beneath it.
- **Entries history:** the aside follows the summary with a compact disclosure. Below 1200 px the complete aside precedes the admitted and waiting groups, as batch 1 specifies. Cancelled date-time text can wrap on mobile rather than causing horizontal scroll.
- **Mobile toasts:** the stack has a dedicated area beneath a vertically scrollable workspace. Its measured height is reserved while notifications exist, keeping primary actions out from under it. Dismissal or expiry of the last toast restores normal document flow. Desktop retains a fixed bottom-right stack.
- **Configuration widths:** 960 px caps the main form column; the 320 px aside sits beside it when space permits from 1200 px. At 1440 px the main column shrinks to accommodate the implemented rail and gutters.
- **`config-draft`:** the missing-for-publication summary sits above the form, without an aside. It is directly relevant to completing the task, and its links lead to the missing fields. The fixture deliberately leaves the reference time zone empty; this is saved illustrative data, not a proposed initial default.
- **`organisation-selector`:** the fixture shows the one current organisation, retaining the action to create another. No second organisation name is invented.
- **Catalogue:** labelled dialog and drawer specimens render inline, using the same classes and content generators as operational overlays, so variants can be compared in one capture. They do not trap focus or dim one another. The existing catalogue content remains below the added control section; button samples use grouped blocks instead of tables. Toast specimens remain inline, with the focused specimen showing its actual focus outline.

The design detector reports the inherited Inter family and repeating-gradient rules in imported legacy `style.css`; the font follows the established contract, and the rendered surfaces use no striped decoration. No design-system change is proposed.
