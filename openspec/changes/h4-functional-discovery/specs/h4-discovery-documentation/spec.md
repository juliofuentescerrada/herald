## ADDED Requirements

### Requirement: H4 has a complete reviewable functional extension

The documentation SHALL define H4 outcomes, actors/permissions, scope/dependencies, concrete Swiss pairing and statistical rules, connected execution/identity/compatibility, incidents/concurrency/recovery, individual/direct-team impact, API/notices/privacy/history, end-to-end journeys and observable target acceptance. It MUST distinguish existing scope, confirmed decisions, proposed defaults and implemented behaviour.

#### Scenario: A reader evaluates the H4 target

- **WHEN** a reader opens `docs/herald-h4-functional-discovery.md`
- **THEN** they can trace a complete Swiss and real connected-consumer journey, its exceptions and proposed rules to baseline decision IDs and future acceptance without interpreting targets as tests executed or prerequisite milestones as complete

### Requirement: Maintained responsibilities stay separate

The documentation SHALL keep decisions in baseline §15, detailed H4 rules in the extension, delivery scope/sequence in the roadmap and future visual inventory in visual direction. Orientation and source conventions MUST link consistently, reserve the unmerged H3 decision range and give unresolved matters a recommendation, owner and decision gate.

#### Scenario: An unresolved product choice is handed off

- **WHEN** a reader follows an H4 policy reference
- **THEN** the baseline owns its proposed status and the extension explains the recommendation and accountable implementation gate without approving policy or duplicating another maintained responsibility

### Requirement: Discovery remains documentation only

The change SHALL preserve implemented specifications, runtime code and the recorded/published event inventory. It MUST record actual documentation checks and independent review findings/resolutions, distinguishing future acceptance from executed validation.

#### Scenario: The documentation PR is reviewed

- **WHEN** a reviewer inspects the change and its validation record
- **THEN** no H4 product target is moved to `openspec/specs/`, no runtime fact is claimed as published and the actual checks, limitations and independent review outcome are visible
