## ADDED Requirements

### Requirement: H2 has a traceable functional definition

The maintained documentation SHALL define H2 actors, authority, lifecycles, functional rules, exclusions, journeys, acceptance scenarios and implementation gates. It SHALL retain the baseline's single decision register and distinguish confirmed direction, author-defined defaults and implemented behaviour.

#### Scenario: A reader finds the H2 definition

- **WHEN** a reader follows the H2 link from the README, roadmap or functional baseline
- **THEN** the detailed extension explains participant/admin separation, self-service, teams, reporting, collaboration, protected history, notices and bounded automation
- **AND** its decisions resolve to the baseline's D-30–38 register without claiming production implementation

#### Scenario: A reader assesses the automation delta

- **WHEN** a reader reviews scheduled registration and minimum-field cancellation
- **THEN** the documentation distinguishes admitted entry count, maximum capacity and check-in readiness
- **AND** it includes manual-close, obsolete-deadline, late-worker, retry and notification scenarios while preserving H1's implemented manual-window history

#### Scenario: A reader prepares a production slice

- **WHEN** a reader uses the discovery to prepare H2 implementation
- **THEN** pending policy/design/visual gates remain explicit and future acceptance is not presented as executed tests
- **AND** implemented specifications and accepted H1 identity contracts remain unchanged by this documentation change
